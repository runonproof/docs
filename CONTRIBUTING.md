# Contributing

Documentation changes must be factual, scoped, and reproducible.

1. Start from the current public docs branch and identify the approved public-contract export version. Keep private source provenance outside public Git.
2. Update every affected page when a product, route, input, output, price, coverage, or safety rule changes.
3. Use synthetic data in examples.
4. Never add secrets, private workspace URLs, opaque internal identifiers, or payment material.
5. Run the build and route tests.
6. Confirm the sidebar and all internal links work on desktop and mobile.
7. State limitations and distinguish internal installation, public documentation, Marketplace submission, and Marketplace publication.

Do not claim a partnership or endorsement without a separate verified agreement.
